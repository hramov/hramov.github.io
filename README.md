# backend/notes

Технический блог на [Astro](https://astro.build). Статьи — это
markdown-файлы в Git: читаются прямо на GitHub, рендерятся в сайт без
переписывания, переезжают куда угодно. Контентом владеешь ты.

---

## Запуск локально

Нужен Node.js 18+ (лучше 20).

```bash
npm install      # один раз
npm run dev      # http://localhost:4321 — с живой перезагрузкой
```

Сборка статики и локальный предпросмотр прод-версии:

```bash
npm run build    # результат в ./dist
npm run preview
```

## Как написать статью

1. Создай папку под статью: `src/content/posts/<slug>/index.md`
   (slug станет адресом: `/posts/<slug>/`).
2. Картинки клади рядом, в `src/content/posts/<slug>/images/`,
   и ссылайся относительно: `![подпись](./images/foo.svg)`.
3. В начале файла — frontmatter:

```yaml
---
title: "Заголовок"
description: "1–2 предложения, попадут в список и в RSS"
pubDate: 2026-06-10
tags: ["rust", "architecture"]
draft: false        # true — не попадёт в сборку
---
```

Дальше — обычный markdown. Подсветка кода работает из коробки.

### Диаграммы (Mermaid)

Пиши прямо в тексте — рисуется автоматически, ничего коммитить не надо:

    ```mermaid
    flowchart LR
      Client --> Gateway --> Service --> DB[(Postgres)]
    ```

Mermaid покрывает flowchart, sequence, ER, state и т.д. PlantUML бери
только когда Mermaid реально не хватает — и тогда рендери в SVG и
коммить картинку (см. ниже).

Смотри живой пример: `src/content/posts/2026-05-rust-memory-leak/` —
там есть и картинка, и Mermaid, и блоки кода. Используй как шаблон,
потом удали.

## Деплой на GitHub Pages

1. Залей репозиторий на GitHub.
2. В `astro.config.mjs` выставь `site` (и `base`, если это
   project-страница `USER.github.io/REPO`).
3. В настройках репозитория: **Settings → Pages → Source → GitHub Actions**.
4. Каждый `git push` в `main` собирает и публикует сайт
   (workflow в `.github/workflows/deploy.yml`).

### Свой домен (рекомендуется — это и есть актив)

Купи домен, в **Settings → Pages → Custom domain** впиши его, у
регистратора настрой DNS на GitHub Pages. После этого:

- в `astro.config.mjs`: `site: 'https://имя.dev'`, `base` убери/`'/'`;
- ссылки идут сразу на твой домен — при будущих изменениях ничего не
  ломается.

## PlantUML (на редкий случай сложных схем)

Держи исходник `.puml` рядом со статьёй, генери SVG и коммить его:

```bash
docker run --rm -v "$PWD:/data" plantuml/plantuml -tsvg "/data/**/*.puml"
```

Потом ссылайся на готовый `.svg` как на обычную картинку.

## Контент-план и привычка

- **Ритм:** 1 пост в 2 недели. Стабильность важнее объёма.
- **Темы:** из своей работы, узкие и конкретные. Идеи копи в `ideas.md`.
- **ИИ:** редактор и спарринг-партнёр, не автор. Технические факты —
  проверяй на первоисточнике.
- **Распространение:** анонс в Telegram-канале + кросс-пост на Хабр с
  указанием каноничного источника (этого сайта).
